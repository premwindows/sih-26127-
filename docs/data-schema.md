# SIH 26127 - Data Schema

## Purpose

This document defines the common data structures exchanged between the AI,
backend, database and frontend components.

The schema may evolve during development, but changes must be communicated
to the team and documented here.

---

# 1. Camera

Represents a camera installed at a known location.

Fields:

- camera_id
- name
- latitude
- longitude
- location_name
- direction
- status

Example:

{
    "camera_id": "CAM01",
    "name": "Main Road Junction",
    "latitude": 28.6139,
    "longitude": 77.2090,
    "location_name": "Junction A",
    "direction": "NORTH",
    "status": "online"
}

---

# 2. Vehicle Detection

Generated by the vehicle detection model.

Fields:

- camera_id
- frame_id
- timestamp
- track_id
- vehicle_type
- confidence
- bounding_box

Example:

{
    "camera_id": "CAM01",
    "frame_id": 1520,
    "timestamp": "2026-08-28T10:02:31",
    "track_id": 17,
    "vehicle_type": "car",
    "confidence": 0.93,
    "bounding_box": {
        "x1": 320,
        "y1": 180,
        "x2": 620,
        "y2": 480
    }
}

---

# 3. License Plate Detection

Generated when a license plate is detected inside a vehicle.

Fields:

- camera_id
- frame_id
- track_id
- timestamp
- plate_bounding_box
- plate_confidence
- plate_image_path

Example:

{
    "camera_id": "CAM01",
    "frame_id": 1520,
    "track_id": 17,
    "timestamp": "2026-08-28T10:02:31",
    "plate_bounding_box": {
        "x1": 410,
        "y1": 350,
        "x2": 520,
        "y2": 390
    },
    "plate_confidence": 0.91,
    "plate_image_path": "data/plates/CAM01_1520.jpg"
}

---

# 4. OCR Result

Generated by the OCR module.

Fields:

- plate_text
- ocr_confidence
- camera_id
- track_id
- timestamp

Example:

{
    "plate_text": "MH12AB1234",
    "ocr_confidence": 0.94,
    "camera_id": "CAM01",
    "track_id": 17,
    "timestamp": "2026-08-28T10:02:31"
}

---

# 5. Vehicle Embedding / Re-ID

Generated by the vehicle Re-ID module.

Purpose:

Provide visual similarity information for matching vehicles across
different cameras.

Fields:

- camera_id
- track_id
- timestamp
- embedding_reference
- vehicle_type

Example:

{
    "camera_id": "CAM01",
    "track_id": 17,
    "timestamp": "2026-08-28T10:02:31",
    "embedding_reference": "data/embeddings/CAM01_track17.bin",
    "vehicle_type": "car"
}

Important:

A Re-ID embedding is evidence for vehicle matching. It should not
automatically be treated as absolute proof that two observations are the
same physical vehicle.

---

# 6. Vehicle Event

This is the main event passed toward the backend.

A Vehicle Event combines information from multiple AI modules.

Fields:

- event_id
- camera_id
- timestamp
- track_id
- vehicle_type
- plate_text
- plate_confidence
- vehicle_confidence
- latitude
- longitude

Example:

{
    "event_id": "EVT_000001",
    "camera_id": "CAM01",
    "timestamp": "2026-08-28T10:02:31",
    "track_id": 17,
    "vehicle_type": "car",
    "plate_text": "MH12AB1234",
    "plate_confidence": 0.94,
    "vehicle_confidence": 0.93,
    "latitude": 28.6139,
    "longitude": 77.2090
}

---

# 7. Trajectory Event

Represents one confirmed/accepted observation of a vehicle in a
multi-camera trajectory.

Fields:

- trajectory_id
- vehicle_identifier
- camera_id
- timestamp
- latitude
- longitude
- sequence_number
- matching_confidence

Example:

{
    "trajectory_id": "TRJ_001",
    "vehicle_identifier": "MH12AB1234",
    "camera_id": "CAM01",
    "timestamp": "2026-08-28T10:02:31",
    "latitude": 28.6139,
    "longitude": 77.2090,
    "sequence_number": 1,
    "matching_confidence": 0.96
}

---

# 8. Complete Trajectory

A complete trajectory consists of multiple trajectory events.

Example:

Vehicle:

MH12AB1234

Observations:

1. CAM01
   10:02:31
   Location A

2. CAM02
   10:10:15
   Location B

3. CAM04
   10:18:42
   Location C

4. CAM07
   10:29:03
   Location D

The frontend can use these points to draw the route on a map.

---

# 9. Traffic Analytics Event

Used for aggregated traffic analysis.

Possible fields:

- camera_id
- time_window
- vehicle_count
- vehicle_type_distribution
- estimated_average_speed
- congestion_level

Example:

{
    "camera_id": "CAM01",
    "time_window": "10:00-10:05",
    "vehicle_count": 82,
    "vehicle_type_distribution": {
        "car": 55,
        "truck": 12,
        "bus": 8,
        "motorcycle": 7
    },
    "estimated_average_speed": 32,
    "congestion_level": "MEDIUM"
}

Note:

Average speed should only be displayed when the system has sufficient
information to estimate it reliably.

---

# 10. Alert

Represents a system-generated alert.

Types may include:

- BLACKLIST_MATCH
- ROUTE_ANOMALY

Fields:

- alert_id
- alert_type
- severity
- vehicle_identifier
- camera_id
- timestamp
- message
- confidence
- status

Example:

{
    "alert_id": "ALT_0001",
    "alert_type": "BLACKLIST_MATCH",
    "severity": "HIGH",
    "vehicle_identifier": "MH12AB1234",
    "camera_id": "CAM01",
    "timestamp": "2026-08-28T10:02:31",
    "message": "Vehicle matched watchlist entry.",
    "confidence": 0.98,
    "status": "UNREAD"
}

---

# 11. Watchlist

Stores vehicles that should generate alerts when detected.

Fields:

- watchlist_id
- plate_text
- reason
- status
- created_at

Example:

{
    "watchlist_id": "WL001",
    "plate_text": "MH12AB1234",
    "reason": "Demo watchlist entry",
    "status": "active",
    "created_at": "2026-08-28T09:00:00"
}

For the SIH prototype, use synthetic/demo watchlist data.

# 14. Important Integration Rule

AI modules should not directly modify frontend code.

Frontend should not directly access the AI modules.

The backend acts as the integration layer.

Preferred architecture:

AI
 ↓
Backend API
 ↓
Database
 ↓
Backend API
 ↓
Frontend

---

# 15. Schema Change Rule

If a team member needs to change a field:

1. Inform the team.
2. Update this document.
3. Update the affected code.
4. Test the integration.
5. Create a Pull Request.

Do not silently change the shared data format.
